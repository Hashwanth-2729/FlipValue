## 1. Architecture

```
Visitors ──HTTPS──▶ Firebase Hosting  (frontend/dist: React SPA, CDN, SPA fallback to index.html)
                       │  rewrites /api/**, /v1/**, /admin/api/**, /openapi.json  (same origin → no CORS)
                       ▼
FixMyTech ──HTTPS──▶ Cloud Run service "flipvalue-api" (asia-south1)  ◀── Cloud Run job "flipvalue-migrate"
                       │  image: Dockerfile (python -m flipvalue serve, 0.0.0.0:$PORT)      (same image: release)
                       │  secrets: Secret Manager → env vars
                       ▼
                 Cloud SQL for PostgreSQL "flipvalue-db" (Unix socket via the Cloud Run Cloud SQL connector)
```

**Why this shape (audit of the repository):**

* The website is a **static single-page app** (React + Vite → `frontend/dist`). It needs no server rendering, so
  Firebase Hosting serves it directly. It calls relative `/api/...` URLs; Hosting rewrites those to Cloud Run, so the
  browser sees one origin, no CORS is needed, and no website code had to change.
* The backend is a **FastAPI application factory** (`flipvalue.app:create_app`) with SQLAlchemy 2 + Alembic. Cloud
  Run runs it unchanged in a container; `python -m flipvalue serve` binds `0.0.0.0:$PORT`.
* **Database: Cloud SQL for PostgreSQL.** The app needs a relational database shared by all instances (rate-limit
  counters, idempotency records, saved valuations, observations). SQLite on Cloud Run would live on an ephemeral,
  per-instance disk and lose data — production now refuses SQLite at startup. Firestore was rejected because it
  would mean rewriting the data layer. The code was tested on PostgreSQL 16.2 locally (§10).
* **Region `asia-south1` (Mumbai)**: most users are in India; Firebase lists it among regions supported for Hosting →
  Cloud Run rewrites (it is not one of the five regions Firebase recommends for lowest Hosting latency). To change
  it, edit `$REGION` below **and** the `region` value of every rewrite in `firebase.json`.
* **FixMyTech calls the Cloud Run URL directly** (`https://…run.app/v1/valuations`): no CDN in between, no 60 s
  Hosting timeout. The Hosting domain also routes `/v1/**`; the smoke test checks that path too.
* **No resource names are invented as existing**: `flipvalue-api`, `flipvalue-migrate`, `flipvalue-db`, `flipvalue`
  (registry and DB) and `flipvalue-run` (service account) are the names these commands *will create*. Your project
  ID is yours to choose.

## 2. Costs and billing — read before creating anything

**This deployment is not free.** Cloud Run, Cloud SQL and Secret Manager require a **Cloud Billing account**; linking
one upgrades the Firebase project to the **Blaze (pay-as-you-go)** plan.

| Service | Free allowance (verify on the official pricing pages) | What will likely cost money |
|---|---|---|
| **Cloud SQL (PostgreSQL)** | **No always-free tier** (new accounts may get trial credit) | **The main fixed cost.** Smallest shared-core `db-f1-micro`: roughly US$8–12/month depending on region, plus storage (10 GB) and backups. Billed every hour the instance exists, even with no traffic |
| Cloud Run | Per month: first 2 million requests, 180,000 vCPU-seconds, 360,000 GiB-seconds (request-based billing, Tier 1 regions; Tier 2 regions have smaller CPU allowances) | Little at low traffic with `--min-instances 0`. Setting min instances > 0 costs money continuously |
| Firebase Hosting | 10 GB storage; 10 GB/month transfer | US$0.026/GB storage and US$0.15/GB transfer beyond that (Blaze) |
| Secret Manager | 6 active secret versions, 10,000 access operations/month | Each key rotation adds a version — destroy old versions. This setup uses 4 secrets |
| Artifact Registry | 0.5 GB storage | Each image is ~150–250 MB: delete old images |
| Cloud Build | A free daily build-minute allowance exists (amount not verified here) | Builds beyond it |
| Cloud Logging | A monthly free ingestion allowance exists (not verified here) | High log volume |

**Risks of unexpected charges:** leaving Cloud SQL running; raising `--max-instances` or `--min-instances`; abusive
traffic (mitigated by rate limits, `--max-instances 3`, and the global public limit); old images and secret versions
accumulating. **Budget alerts notify you but do not stop spending.** To stop all charges, run §9 (teardown).

Sources: [Cloud Run pricing](https://cloud.google.com/run/pricing), [Firebase Hosting quotas and pricing](https://firebase.google.com/docs/hosting/usage-quotas-pricing),
[Cloud SQL pricing](https://cloud.google.com/sql/pricing), [Secret Manager free tier announcement](https://cloud.google.com/blog/products/identity-security/google-cloud-secret-manager-adds-free-of-charge-tier-and-more),
[Firebase Hosting + Cloud Run](https://firebase.google.com/docs/hosting/cloud-run). Prices change; check them on the day you deploy.

## 3. Tools you need

* Google Cloud SDK (`gcloud`): <https://cloud.google.com/sdk/docs/install>
* Firebase CLI: `npm install -g firebase-tools`
* Python 3.11+ and Node 20+ (already set up for local development). **Docker is not needed**: Cloud Build builds the image.

Commands below are **PowerShell**. Set these first (choose your own project ID):

```powershell
$PROJECT_ID   = "<your-project-id>"          # globally unique, e.g. flipvalue-<something>
$REGION       = "asia-south1"
$SERVICE      = "flipvalue-api"
$JOB          = "flipvalue-migrate"
$SQL_INSTANCE = "flipvalue-db"
$REPO         = "flipvalue"
$SA_NAME      = "flipvalue-run"
$SA           = "$SA_NAME@$PROJECT_ID.iam.gserviceaccount.com"
$CONN         = "${PROJECT_ID}:${REGION}:${SQL_INSTANCE}"
```

## 4. One-time setup (requires your account)

```powershell
# 4.1 Sign in and create/select the project (or create it in the console and skip projects create)
gcloud auth login
gcloud projects create $PROJECT_ID          # skip if it already exists
gcloud config set project $PROJECT_ID
#   → Console: link a billing account to the project (Billing → Link a billing account), then create a budget alert.

# 4.2 Enable APIs
gcloud services enable run.googleapis.com sqladmin.googleapis.com secretmanager.googleapis.com `
  artifactregistry.googleapis.com cloudbuild.googleapis.com iam.googleapis.com

# 4.3 Image registry and a dedicated runtime service account (least privilege)
gcloud artifacts repositories create $REPO --repository-format=docker --location=$REGION
gcloud iam service-accounts create $SA_NAME --display-name "FlipValue Cloud Run"
gcloud projects add-iam-policy-binding $PROJECT_ID --member "serviceAccount:$SA" --role roles/cloudsql.client

# 4.4 Cloud SQL for PostgreSQL (starts billing). Takes several minutes.
gcloud sql instances create $SQL_INSTANCE --database-version=POSTGRES_16 --edition=ENTERPRISE `
  --tier=db-f1-micro --region=$REGION --storage-type=SSD --storage-size=10 --availability-type=ZONAL `
  --backup-start-time=21:00 --deletion-protection
gcloud sql databases create flipvalue --instance=$SQL_INSTANCE
$DB_PASSWORD = python -c "import secrets; print(secrets.token_urlsafe(24))"
gcloud sql users create flipvalue --instance=$SQL_INSTANCE --password=$DB_PASSWORD

# 4.5 Secrets (values are generated and piped straight into Secret Manager; nothing is written to disk)
"postgresql+psycopg://flipvalue:$DB_PASSWORD@/flipvalue?host=/cloudsql/$CONN" | gcloud secrets create flipvalue-database-url --data-file=-
python -c "import secrets; print(secrets.token_urlsafe(32))" | gcloud secrets create flipvalue-hash-salt --data-file=-
python -c "import secrets; print(secrets.token_urlsafe(32))" | gcloud secrets create flipvalue-partner-keys --data-file=-
python -c "import secrets; print(secrets.token_urlsafe(32))" | gcloud secrets create flipvalue-admin-keys --data-file=-
Remove-Variable DB_PASSWORD
foreach ($s in "flipvalue-database-url","flipvalue-hash-salt","flipvalue-partner-keys","flipvalue-admin-keys") {
  gcloud secrets add-iam-policy-binding $s --member "serviceAccount:$SA" --role roles/secretmanager.secretAccessor
}
```

If `gcloud builds submit` later fails with a permission error, grant the build service account named in the error
`roles/artifactregistry.writer` and `roles/logging.logWriter` (newer projects build with the Compute Engine default
service account).

## 5. Deploy the backend

```powershell
$TAG   = Get-Date -Format "yyyyMMdd-HHmmss"
$IMAGE = "$REGION-docker.pkg.dev/$PROJECT_ID/$REPO/api:$TAG"
$SECRETS = "FLIPVALUE_DATABASE_URL=flipvalue-database-url:latest,FLIPVALUE_HASH_SALT=flipvalue-hash-salt:latest,FLIPVALUE_API_KEYS=flipvalue-partner-keys:latest,FLIPVALUE_ADMIN_KEYS=flipvalue-admin-keys:latest"

# 5.1 Build the image in Cloud Build (uploads only what .gcloudignore allows)
gcloud builds submit --tag $IMAGE .

# 5.2 Database schema + catalogue: a Cloud Run job running `python -m flipvalue release` (idempotent)
gcloud run jobs create $JOB --image $IMAGE --region $REGION --service-account $SA `
  --set-cloudsql-instances $CONN --set-secrets $SECRETS `
  --command python --args="-m,flipvalue,release" --max-retries 0 --task-timeout 300
gcloud run jobs execute $JOB --region $REGION --wait

# 5.3 The API service (first deployment)
gcloud run deploy $SERVICE --image $IMAGE --region $REGION --service-account $SA `
  --add-cloudsql-instances $CONN --set-secrets $SECRETS `
  --set-env-vars "FLIPVALUE_PROXY_HOPS=1,FLIPVALUE_DB_POOL_SIZE=3,FLIPVALUE_DB_MAX_OVERFLOW=2" `
  --allow-unauthenticated --min-instances 0 --max-instances 3 --concurrency 40 `
  --cpu 1 --memory 512Mi --timeout 30 --port 8080

$API_URL = gcloud run services describe $SERVICE --region $REGION --format "value(status.url)"
$API_URL
```

`--allow-unauthenticated` is required: Firebase Hosting rewrites and FixMyTech reach the service without Google IAM
credentials. Access control is FlipValue's own: partner and admin endpoints require `X-API-Key`; `/api` (website) is
public by design and rate-limited.

Connection budget: 3 instances × (3 + 2) = 15 connections, below `db-f1-micro`'s limit (about 25; check with
`SHOW max_connections;`). Raise instances only together with a larger database tier.

```powershell

Copy-Item .firebaserc.example .firebaserc       # then edit .firebaserc: replace YOUR-FIREBASE-PROJECT-ID with $PROJECT_ID

firebase hosting:channel:deploy preview --expires 7d
#   → copy the printed preview URL, then:
$env:FLIPVALUE_SMOKE_API_KEY = gcloud secrets versions access latest --secret=flipvalue-partner-keys
python scripts/smoke_test.py --api-url $API_URL --site-url "<preview URL>"

# 6.2 Go live
firebase deploy --only hosting
python scripts/smoke_test.py --api-url $API_URL --site-url "https://$PROJECT_ID.web.app"
```

The Cloud Run service must exist before the first Hosting deploy; Firebase rejects rewrites to a missing service.

**6.3 Verify the client-IP setting (one time).** Rate limiting per visitor depends on how many proxies sit in front of
Cloud Run on the website path. With the admin key, call the diagnostics endpoint *through the website*:

```powershell
$admin = gcloud secrets versions access latest --secret=flipvalue-admin-keys
Invoke-RestMethod "https://$PROJECT_ID.web.app/admin/api/diagnostics/forwarding" -Headers @{ "X-API-Key" = $admin }
Remove-Variable admin
```

`client_ip_used_for_rate_limits` must be **your own public IP**. If it shows a Google address instead, find your IP's
position from the right in `x_forwarded_for` and set it:
`gcloud run services update $SERVICE --region $REGION --update-env-vars FLIPVALUE_PROXY_HOPS=<n>`.
(The global public limit protects the database even if this is wrong.)

## 8. Operating

**Logs** (JSON lines; `severity`, `message`, `request_id`, `status`, `latency_ms`; never keys, bodies or IPs):

```powershell
gcloud logging read 'resource.type="cloud_run_revision" AND resource.labels.service_name="flipvalue-api"' --limit 50 --freshness 1d
gcloud logging read 'resource.type="cloud_run_revision" AND resource.labels.service_name="flipvalue-api" AND severity>=WARNING' --limit 50
gcloud logging read 'resource.type="cloud_run_job" AND resource.labels.job_name="flipvalue-migrate"' --limit 50
gcloud logging read 'jsonPayload.request_id="<id from an error response>"' --limit 10
```

Console: Cloud Run → flipvalue-api → Logs / Metrics. Aggregates: `GET /admin/api/metrics` (admin key).

**Updating the backend** (zero-downtime, test before traffic moves):

```powershell
$TAG = Get-Date -Format "yyyyMMdd-HHmmss"; $IMAGE = "$REGION-docker.pkg.dev/$PROJECT_ID/$REPO/api:$TAG"
gcloud builds submit --tag $IMAGE .
gcloud run jobs update $JOB --image $IMAGE --region $REGION
gcloud run jobs execute $JOB --region $REGION --wait                 # migrations must keep the old revision working
gcloud run deploy $SERVICE --image $IMAGE --region $REGION --no-traffic --tag candidate
#   test the tagged URL printed by the command (https://candidate---…run.app):
python scripts/smoke_test.py --api-url "<candidate URL>"
gcloud run services update-traffic $SERVICE --region $REGION --to-latest
```

**Updating the website:** `npm --prefix frontend run build`, preview channel (§6.1), then `firebase deploy --only hosting`.

**Rolling back**

* API: `gcloud run revisions list --service $SERVICE --region $REGION`, then
  `gcloud run services update-traffic $SERVICE --region $REGION --to-revisions <previous-revision>=100`.
  (Later, `--to-latest` sends traffic to the newest revision again.)
* Website: Firebase console → Hosting → Release history → ⋮ → **Rollback**.
* Database: migrations are forward-only. Before risky migrations take an on-demand backup:
  `gcloud sql backups create --instance $SQL_INSTANCE`; restore with `gcloud sql backups list --instance $SQL_INSTANCE`
  and `gcloud sql backups restore <BACKUP_ID> --restore-instance $SQL_INSTANCE` (overwrites current data).

**Rotating a secret** (example: partner key)

1. `"<old>,<new>" | gcloud secrets versions add flipvalue-partner-keys --data-file=-` (generate `<new>` with Python).
2. New revision picks it up: `gcloud run services update $SERVICE --region $REGION --update-labels rotated=$TAG`.
3. Give FixMyTech the new key; once they switched, add a version with only `<new>`, update again, then
   `gcloud secrets versions destroy <old-version> --secret flipvalue-partner-keys`.

The same pattern works for the admin key. Changing `flipvalue-hash-salt` only resets rate-limit counters. For the
database password: `gcloud sql users set-password flipvalue --instance $SQL_INSTANCE --password <new>`, then add a new
`flipvalue-database-url` version and update the service and job.

**Retention:** run `python -m flipvalue purge` daily, e.g. a second job:
`gcloud run jobs create flipvalue-purge --image $IMAGE --region $REGION --service-account $SA --set-cloudsql-instances $CONN --set-secrets $SECRETS --command python --args="-m,flipvalue,purge"`
and a Cloud Scheduler trigger (console → Cloud Run → Jobs → flipvalue-purge → Triggers).

## 9. Teardown (stops charges)

```powershell
gcloud run services delete $SERVICE --region $REGION
gcloud run jobs delete $JOB --region $REGION
gcloud sql instances patch $SQL_INSTANCE --no-deletion-protection
gcloud sql instances delete $SQL_INSTANCE          # deletes all data and its backups
gcloud artifacts repositories delete $REPO --location $REGION
foreach ($s in "flipvalue-database-url","flipvalue-hash-salt","flipvalue-partner-keys","flipvalue-admin-keys") { gcloud secrets delete $s }
firebase hosting:disable
```
